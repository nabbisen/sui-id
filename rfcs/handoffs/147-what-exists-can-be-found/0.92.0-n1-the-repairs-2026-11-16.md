## §3 — a missing configuration says how to make one (RFC 147 §3)

**Where:** in `Config::load` (`crates/sui-id/src/runtime/config.rs:229-236`),
not in its callers. It has **ten callers**: the server (`main.rs:122`) and
nine commands in `cli.rs` (`:78`, `:108`, `:169`, `:306`, `:352`, `:405`,
`:514`, `:811`, `:1148`). One place covers every one of them, and covers any
command added later.

**Only the not-found case changes.** Today `read_to_string`'s error is one
message for every failure (`config.rs:230-231`). Split it:
- **`NotFound`** → the three parts the RFC lists, in order;
- **every other read error**, a parse error, or a validation error → its
  current message, unchanged.

**One correction to the RFC: there is no deployed documentation site.** The
book is built in CI and never published. So *"the configuration reference"*
is named by **its source on GitHub, pinned to this binary's own release
tag**: `https://github.com/nabbisen/sui-id/blob/{version}/docs/src/reference/configuration.md`,
with `{version}` from `env!("CARGO_PKG_VERSION")`. A `0.92.0` binary then
always links the `0.92.0` documentation, never a newer `main` that describes
things it does not do. **The same rule applies to §2's link.** Build both from
one helper, so the base URL is written once.

The message, as a guide (keep its three parts and their order):

```text
Error: no configuration file at ./sui-id.toml

  Create one to start from:
      sui-id --print-sample-config > sui-id.toml      (a local trial)
  The production template is sui-id.example.toml, in a source checkout.
  Reference: https://github.com/nabbisen/sui-id/blob/0.92.0/docs/src/reference/configuration.md
```

**Test**, as the RFC says: through the binary, in an empty directory, three
times (no argument; `setup --admin-username admin`; `--config ./missing.toml`).
Assert each part, and that the URL contains the binary's own version.
**Mutation:** restore the bare error.

## §4 — the production template names every key (RFC 147 §4)

`sui-id.example.toml` gains `user_sources`, `federation_providers`,
`metrics_enabled`, `metrics_listen_addr` and `access_log`, each set or
commented with its default under its section, as `Config::sample()`
(`config.rs:239`) serializes them. **Do not change the template's
production-oriented values.** **Test and mutation** as the RFC says: parse the
template as a `Config`, and require every key `Config::sample()` serializes.
