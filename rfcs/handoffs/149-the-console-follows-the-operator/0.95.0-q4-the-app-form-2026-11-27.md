## §1: scopes (RFC 149 §4, first item)

- **The standard scopes are checkboxes, generated from the list discovery advertises.**
  - Make that list one named constant, used by discovery and by the form, so they cannot drift.
  - A scope added to it appears in both. Test it (§5).
- **`openid` is fixed on.** It is shown checked and disabled, and **the server includes it whatever is submitted**. OpenID
  Connect requires it, and a disabled checkbox sends nothing.
- **Additional scopes**, for an operator's own API, are a separate text field, placed under a layer-2 help (`help_details`,
  Q3). Each space-separated token is checked on the server:
  - **the syntax of RFC 6749 §3.3**: `scope-token = 1*( %x21 / %x23-5B / %x5D-7E )`. Anything else is refused, naming the
    token;
  - **a standard scope typed here** (`email`) is refused, with: tick it above;
  - **a near miss of a standard scope is refused**, offering the standard name. That is one edit away (`profle`,
    `emial`), or differing only in case (`Profile`). Implement the distance once, and test it on its own;
  - a duplicate is saved once.
- **Apps saved before this release** (the plan, §2): an app whose stored scopes include a near miss cannot be saved again
  until it is corrected. The form shows the stored value in *Additional scopes*, with the same message. Nothing that worked
  stops working, because a near miss never took effect. The upgrade note says so (the release preparation writes it; list
  the fact in your return).

## §2: one input per URI (RFC 149 §4, second item)

For redirect URIs, and for post-logout URIs:
- **One `<input>` per URI**, each with a *Remove* button, and an *Add another* button.
- **With JavaScript off**, *Add another* and *Remove* are submit buttons:
  - with a distinct `name`/`value`, so the server knows which was pressed;
  - **the server returns the form with what was typed preserved**, one row more or one fewer;
  - **it saves nothing and records nothing**.

  Only the form's *Save* (or *Create*) saves.
- **A static script may add or remove the row in place**: a file under `/static/`, with no inline script (`script-src
  'self'`). The page must work the same without it.
- **Each URI is checked on its own, and an error names the URI that failed**, never a line number. All the URIs' errors are
  shown at once, each beside its own input.
- **Parsing the repeated fields: no new crate.** No new crate may enter `Cargo.lock`. `form_urlencoded` is already in the
  tree, and indexed names (`redirect_uri_0`, …) parse with today's `Form`. Choose, and say why.

## §3: create and edit are one form (RFC 149 §4, third item)

- **One component renders both.** Fields that exist only after creation (the client ID, the secret's state, the dates) are
  listed on edit, each with its one-line reason (RFC 147 §5).
- Fields that today differ between the two forms only by accident are made the same. List every difference you found, and
  what you did with it.
