## §1: help in three layers (RFC 149 §3)

**Layer 1, always shown: every page states its purpose in one line.**
- Each page rendered with the console's chrome or the account chrome has a non-empty `page-header__lede`.
- Measured at `57c80d1`: the `/me` pages have none (`me_security/overview.rs`, `mfa.rs`, `passkey.rs`, `sessions.rs`,
  `language.rs`). Give each one.
- **A hint under a field stays only where a reader would make a mistake without it** (RFC 149 §3's test). Do not add hints
  to fields whose label is enough.

**Layer 2, on request: a `?` beside a section, opening in place.**
- One shared component: a `<details class="help">` whose `<summary>` is a visible **?** with an accessible name, for
  example *"About session limits"*. It opens with a click, a tap or the keyboard, with no JavaScript.
- **At most three sentences, then *Learn more*.** *Learn more* is a link made with `github_doc_url!`
  (`crates/sui-id-web/src/doc_links.rs`), so it names the documentation as it stood at this binary's own release.
- **Where**: one per section listed below, no more. Each list item is a page, then its sections.
  - **Signing keys**: rotation.
  - **Sessions and lockout**: session limits; lockout.
  - **Sign-in settings**: the minimum password length; two-step verification.
  - **Email**: SMTP and TLS.
  - **Federation providers**: what *requires review* means.
  - **Audit log**: the chain check.
  - **About this server**: the storage paths.

  Write the text from what the code does, and **check every sentence against the code** before writing it. The app form's
  help is Q4's.
- **Learn more goes to a page that exists.** A test scans every `github_doc_url!("…")` path in `crates/sui-id-web/src` and
  fails if the file is not under the repository root. If an anchor follows (`#…`), it also fails when no heading in that
  file has that slug.

**No hover-only tooltip anywhere.**
- Measured at `57c80d1`: the copy buttons still carry `title=`: `pages/common.rs:157` and `components/utilities.rs:373`.
- **Remove both.** The button's visible label (*Copy*) and its accessible name (*Copy client ID*) stay. The field beside it
  says what is copied.

## §2: the first-run path (RFC 149 §2)

The dashboard's *Getting started* card (`pages/dashboard.rs`, RFC 073's three items) becomes **an ordered path of five
steps**. Each step has its status and a direct link:

| # | Step | Status, from | Link |
|---|---|---|---|
| 1 | Protect your administrator account | **Done** when the person viewing has a second factor (`users::has_mfa`, as `gs_admin_mfa` reads it today) | `/me/security/mfa` |
| 2 | Set up email (password reset and recovery need it) | **Done** when SMTP is configured (`gs_smtp_configured`) | System → Email |
| 3 | Add your first app | **Done** when at least one app exists (`gs_first_app_added`) | `/admin/clients/new` |
| 4 | Review sign-in and session settings | **Recommended**: always this label, **never a done state** | Sign-in settings, and Sessions and lockout |
| 5 | Add a federation provider | **Optional**, or **Done** when at least one provider exists | *Learn more*, to the operator's guide (there is no console form yet) |

- **Steps 4 and 5 never hold the path open.** When steps 1 to 3 are done, the path folds to one line (*"Getting started:
  done"*), which is a `<details>` that can be reopened. While any of steps 1 to 3 is open, the path shows open.
- **Every step shows its status in words**, not only by colour or a tick: *Done*, *Recommended*, *Optional*, or nothing
  (still to do). A blank status beside step 4 would look broken, so it always says *Recommended*.
- **Who sees it: an administrator.** An auditor cannot do steps 2 to 5, so the path is not shown to an auditor. The handler
  has the role (`CurrentAdminOrAuditor(admin_id, _role, …)`, `handlers/admin/dashboard.rs:15`); pass it through.
- **No prompt twice.** The *Action required* list's *"SMTP is not configured"* item is not shown while step 2 is open on the
  path, because the path already says it. The other action items stay as they are.

## §3: the dashboard says what needs attention

Two items join the existing *Action required* list (`pages/dashboard.rs`). That list is what the dashboard already uses for
this purpose; do not add a second section.

1. **A kept master-key backup past its review date.**
   - Today it is only a server-start `WARN` and a line in `admin master-key rotate --check`
     (`runtime/rotate/backup.rs`, `overdue_finding_text`).
   - Read it **on each dashboard request**, from `state.db` (`master_key_rotation::read`), so that a `backup renew` or
     `backup remove` made while the server runs is reflected. Measure the read's cost and say it in the return.
   - **The item states**: that a kept backup is past its review date; that date; its custody reference; that it is settled
     with `sui-id admin master-key backup remove` or `backup renew`; and *Learn more* to the operator's guide, *Rotating the
     master key* (`docs/src/guides/operators.md:134`).
   - **It shows no filesystem path.** The command's own report has it, for the operator at the host.
   - **Share one predicate with `overdue_finding_text`**: what counts as overdue is decided in one place. Do not write a
     second comparison.
2. **A federation provider that requires review**: how many, linking to *Federation providers*. The same interim as
   `runtime/startup.rs:420`'s warning.

**Measured, and to fix here**: at 375px, the dashboard's range tabs (`.sparkline-header > nav.app-nav.flex-0-auto`) are
401px wide, so the page scrolls sideways (Q2's return; Q2's review re-measured it). They must wrap or fit at 375px.

## §4: each DNS deny reason gets a short localized label

`fed_cause_dns_denied` puts the deny table's English registry name into every locale's page. That name is sometimes long,
for example *"IPv4-compatible Address -- RFC 4291 S2.5.5.1 …"* (`runtime/resolver.rs`, 52 rows).
- Give `DeniedPrefix` a **class**: an enum of a few kinds a reader understands. For example: private network, loopback,
  link-local, documentation, multicast, broadcast or unspecified, translation or tunnel, reserved for special use.
  - Assign every one of the 52 rows a class, and list them in the return.
  - **Keep the registry name** for the logs and the tests that use it.
- The page shows the class's localized label, through an exhaustive `match`, so a new class cannot compile without one.
  `DnsOutcome::Denied` and `TransportCause::DnsDenied` carry the class, not the name.
- If a row fits no class without stretching it, stop and say so. Do not invent a class to hold one row.

## §5: one language chain for every page

The decision is recorded at the top of this dispatch. Measured at `57c80d1`, there are two chains:
- **Console pages** call `resolve_admin_locale` (`http/handlers.rs`), 42 times: the person's preference, then
  `server_settings.default_lang`, then `ja`.
- **Every other page** uses the `RequestLocale` extractor: the preference, then the `sui_id_lang` cookie, then
  `Accept-Language`, then the server default.

So a person with no saved preference can see the console in one language and their own pages in another. Q2's review saw it
happen. Make it one chain:
- **Every console handler takes `RequestLocale`.** Delete `resolve_admin_locale`.
- **One fallback.** Choose which of `ja` and `Locale::default()` is the last fallback, after the server default, and say why.
  The two chains disagree on it today.
- **System → General's hint** for the default language (`settings_basic_default_lang_hint`) must state the real order. That
  is: the default applies only when the person has no saved preference, the language cookie is absent, and the browser's
  `Accept-Language` matches no supported language. **It says that today, and it is false for the console.** After this, it
  is true for every page.
- **CHANGELOG, *Changed*:** the console now follows the browser's language, like every other page, when the person has
  saved no preference. Say what an operator who relied on the server default should do: save a personal language.
