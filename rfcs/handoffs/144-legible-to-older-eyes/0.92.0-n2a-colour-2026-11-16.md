## §1 — the tokens

Set every colour token in `crates/sui-id-web/src/tokens.rs`, in all three mode
blocks (`:root` light, `[data-theme="dark"]`, and the auto-dark block under
`@media (prefers-color-scheme: dark)`), to the values in
`palette-b-tokens-2026-11-16.md`'s output. **Copy the hex values from that
file. Do not recompute or round them.**

Changes in token **names**, beyond values:
- **`--border-control`, new**: the 3:1 control boundary (RFC 144 §2's split).
  It takes the value the palette file lists as `--border-default`.
  **`--border-default` stays** as a non-control line. Set it to the midpoint of
  `--border-control` and `--surface-elevated` (sRGB, 50%), and state the value
  you set in the return.
- **`--danger-emphasis`, new**: the danger button's hover fill.
- **`--devmode-bg`, `--devmode-fg`, `--devmode-warn`, new**: one value each, in
  `:root` only (the banner is the same in both modes).
- **Remove `--fg-on-warning`, `--fg-on-success` and `--fg-on-info`.** Rule 3:
  warning, success and info are never fills that carry text. No component uses
  them today (`grep` over `crates/sui-id-web/src`, outside `tokens`).

**`prefers-contrast: more`** (R5), a new block after `prefers-reduced-motion`:

## §2 — the gate covers what components compose (RFC 144 §1, closure)

`crates/sui-id-web/src/tokens/tests.rs` reads `TOKENS_CSS` and nothing else.
**Widen it to `components_css()`** (`crates/sui-id-web/src/components.rs:95`),
the stylesheet every page actually receives.

**What a composed pair is**, for the gate. For every rule in
`components_css()`:
- a rule that sets **`color:`** contributes (that colour, its own
  `background:` if it sets one). If it sets none, it contributes that colour on
  **each of the four surfaces**;
- a rule that sets **`background:`** without `color:` contributes
  (`--fg-default`, it) **and** (`--fg-muted`, it), because inherited text of
  either kind sits on it;
- **every colour in `components_css()` must be a `var(--token)`.** A literal
  (`#…`, `rgb(…)`) or `color-mix(…)` is a failure, because the gate cannot
  resolve the pair. Today there are six: `buttons.rs:60`,
  `badges.rs:49`, `confirm.rs:27`, `banners.rs:97`, `:98` and `:107`. §3
  replaces each;
- **a translucent token** (`--state-hover`, `--state-active`, seven uses as a
  `background:` today) is composited over each of the four surfaces, and the
  pair is checked on each result.

**What it asserts, per mode** (light, dark, auto-dark, and the two
`prefers-contrast: more` overlays):
- every composed text pair: **7:1** (R1). No text is large enough to claim
  4.5:1 today; if the gate meets one, it fails, and the return says where;
- `--fg-on-accent` on `--accent-default` and `--accent-emphasis`, and
  `--fg-on-danger` on `--danger-default` and `--danger-emphasis`: **7:1**;
- `--border-control`, `--state-focus`, and `--warning-default`,
  `--success-default`, `--info-default` on every surface: **3:1** (R4);
- under `prefers-contrast: more`, `--border-control`: **4.5:1** (R5);
- **only `--accent-default` and `--danger-default` appear as a `color:` among
  the semantic colours** (R3). Warning, success or info as `color:` fails;
- **`prefers-contrast: more` and `prefers-reduced-motion` both exist** in
  `TOKENS_CSS`, asserted by one test (the closure's *"by the same gate"*).

**Delete the exclusion and its prose** (`tokens/tests.rs:13-15`, *"Decorative
tokens … are excluded by design"*). Replace `TEXT_PAIRS` with the derived pairs
above, plus the fill pairs. The doc comment states the five rules and that no
token is excused.

**Tests and mutations**, each run and reverted, each quoted red in the return:

2. Put `color: var(--success-default)` back on `.badge--ok`: red under R3.
3. Put `color: #FFFFFF` back on `button.danger`: red as an unresolvable

4. Delete the `prefers-contrast` block: red.
