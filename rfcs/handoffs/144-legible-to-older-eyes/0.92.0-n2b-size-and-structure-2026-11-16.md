## §1 — the type scale and spacing honour the reader's font size (RFC 144 §3)

`crates/sui-id-web/src/tokens.rs:117-129` sets every size in `px`.

| Token | Today | Becomes |
|---|---|---|
| `--font-size-display` | `28px` | `1.75rem` |
| `--font-size-h2` | `22px` | `1.375rem` |
| `--font-size-h3` | `18px` | `1.125rem` |
| `--font-size-body` | `15px` | **`1rem`** (16px: the RFC raises it) |
| `--font-size-caption` | `13px` | **`0.875rem`** (14px: the RFC raises it) |
| `--space-1` … `--space-6` | `4px` … `48px` | `0.25rem` … `3rem`, the same values ÷ 16 |

**Every other `font-size` in the components** follows: `chrome.rs:88`
(`0.92em`), `:288` (`1em`), the `.button__icon` glyph (`1.25rem`, N2a),
`utilities.rs:65` (`0.85em`), `:153` (`0.8em`). `em` and `rem` are both
relative, so they may stay. **No `px` font size anywhere.**

**Test**, in `tokens/tests.rs`: no `font-size` in `TOKENS_CSS` or
`components_css()` is in `px`, and no `--font-size-*` or `--space-*` token is
in `px`. **Mutation:** set `--font-size-body` back to `15px`; red.

**Borders and the 1px visually-hidden utility stay `px`.** They are not text
or spacing.

## §2 — standalone controls reach 44×44 (RFC 144 §4)

`components/buttons.rs:28`: `min-height: 36px` → **`2.75rem`** (44px at the
default size, and larger when the reader's font size is), with `min-width:
2.75rem`. Form controls (`input`, `select`, `textarea`'s single line), menu
items (`.user-menu__item`) and the theme toggle's buttons
(`components/chrome.rs:377`, today `min-height: auto`) reach the same.

**Not inline links in prose**, which WCAG 2.5.8 exempts: `.link-button`
(`buttons.rs:100`, `min-height: auto` at `:108`) stays as it is, and so does any `<a>`
inside running text.

**Test:** every rule in `components_css()` whose selector names `button`,
`.button`, `input`, `select`, `.user-menu__item` or `.theme-toggle__btn`,
and that sets `min-height` or `height`, sets at least `2.75rem`. The
link-style button is on a named list with its reason, as N1's `empty_state`
list was. **Mutation:** put `36px` back; red. Then **walk it** (§7).

## §3 — no placeholder carries guidance (RFC 144, *Refresh*)

Every `placeholder=` in a page becomes visible hint text under its field
(`field__hint`, which clears 7:1 and stays while the reader types), and the
attribute goes:

| Where | Field |
|---|---|
| `pages/audit.rs:97` | the audit filter |
| `pages/me_security/passkey.rs:66` and `:118` | the passkey nickname (two forms) |

The hint is linked to its field with `aria-describedby`, as existing hints are.

interim). An example may stay inside the hint (*"For example: YubiKey 5C"*).

**Test:** no `placeholder=` in any page under `src/pages`, subdirectories

`components_css()`. **Mutation:** put one back; red.

## §4 — the account menu on every page that shows the navigation (RFC 144, *Refresh*)

**Today:** `layout.rs`'s `Nav` renders the account menu only when the page
passes `admin_username` (`layout.rs:50-54`, `:171-193`), and **only the
dashboard does** (`pages/dashboard.rs:197`). The other 38 `show_nav=true`
uses, in 21 files, fall through to a bare *Sign out* beside *Settings*
(`layout.rs:194-206`).

**Make the type carry it, so no page can forget it again.** Replace the pair
`show_nav: bool` and `admin_username: Option<String>` with one required
prop: the navigation **is** the signed-in person's name, or there is no
navigation. For example:

```rust
pub enum Chrome {
    /// The console navigation, with the account menu for `username`.
    Console { username: String },
    /// No navigation: sign-in, setup, error pages.
    Bare,
}
```

Then **delete the fallback branch** (`layout.rs:194-206`) and its CSS
(`.app-nav__signout`, `.app-nav__signout-form`: `components/chrome.rs:159`,
`:161`, `:166`). Every `show_nav=true` page receives the name from its handler.
The handlers already know who is signed in: `CurrentAdmin` and
`CurrentAdminOrAuditor` carry the user's ID (`http/handlers.rs:223`, `:257`),
and many handlers already load that user (`users_get`,
`http/handlers/admin/users.rs`). **Resolve the name in one place**, not in 38.
If that means the extractor carries it, say so in the return.

**The menu's contents do not change:** *My account*, *Sign out*
(`layout.rs:178-192`).

**Tests:**
- the layout renders `class="user-menu"` with the name for `Console`, and no
  navigation for `Bare`;
- **e2e, signed in, over every route that renders the navigation**: the
  response has the account menu and no `app-nav__signout`. Build the route
  list from the 21 files above and state its length in the return. A route
  you could not reach signed in is named, with why;
- **mutation:** restore the fallback branch and pass `Bare` from one
  handler's page; the e2e test fails for that route.

## §5 — the confirmation's reason says what it is for (N2a review, F5)

`pages/confirm.rs:122-134` picks the reason field's label by whether a reason
is required, not by the action. So the four confirmations with an optional
reason (deleting a user, resetting MFA, deleting an app, deleting a signing
key: `confirm.rs:256`, `:297`, `:382`, `:424`) all say *"Reason for disabling
(optional)"*, with example reasons for disabling. None of them disables
anything.

- Rename `disable_reason_label` / `_placeholder` / `_hint` to
  `optional_reason_label` / `_hint` (the placeholder goes, §3), in en, ja and
  zh-Hans (zh-Hant delegates). They are used only in `pages/confirm.rs:131-133`.
- The label: *"Reason (optional)"*, matching the required form's *"Reason
  (required)"* (`recovery_reason_label`). The hint keeps today's: *"Recorded
  in the audit log so future administrators can understand the context."*
- **Test:** each of the four confirmations renders *"Reason (optional)"*, and
  no confirmation renders the word *disabling* unless its action disables.

## §6 — signed out says so, and tables are denser (RFC 144, *Refresh*)

- **Signed out.** Sign-out already lands on the sign-in page with a flash
  (`http/handlers/admin/auth.rs:1080`, `signed_out_flash`). Make it say
  it plainly: *"You are signed out."* (ja: *"サインアウトしました。"* is
  already plain; zh-Hans: *"您已退出登录。"*). **e2e:** sign in, sign out,
  follow the redirect: the page says so, and the session cookie no longer
  opens `/admin`.
- **Table density** (RFC 144, *What else moves*): table cells' vertical
  padding becomes `--space-2` (`components/tables.rs:53`, today
  `--space-3`). With §1's sizes, a row stands at about 44px.
