## What is wrong, measured

A signed-in person who is **not** in the console (`role` cannot read the
admin console: neither admin nor auditor) opens their own *My account*
pages. Measured on the folded preparation tree, with the dev seed's `alice`
signed in through the dev client's OIDC flow: `/me/security/overview`
renders the full console navigation, *Dashboard, Users, Apps, Signing keys,
Federation providers, Audit log, Settings*. `/admin/users` then answers
`403`. The server enforces access; the page offers what the person cannot
use.

**Where:** every `/me` page passes `Chrome::Console`: `pages/me_security/`
`overview.rs:104`, `mfa.rs:75`, `passkey.rs:93`, `sessions.rs:69`,
`language.rs:35`, `apps.rs:105`; and `pages/auth.rs:239`
(`render_mfa_setup`) and `:322` (`render_password_change`), which the `/me`
handlers render (`handlers/me_security/mfa.rs:107`, `password.rs:30`). The
handlers take `CurrentUser` (any signed-in person).

## §1 — a third state, chosen by the console's own predicate

`Chrome` (`layout.rs`) gains a state for a signed-in person outside the
console: **the account menu, and no console links.** For example:

```rust
pub enum Chrome {
    /// The console navigation, with the account menu for `username`.
    Console { username: String },
    /// Signed in, but not in the console: the account menu alone.
    Account { username: String },
    /// No navigation: sign-in, setup, error pages.
    Bare,
}
```

**Which one a `/me` page gets is decided by the predicate the console's own
gate uses**, `Role::can_read_admin()` (`CurrentAdminOrAuditor`,
`http/handlers.rs:285`), so the navigation offered and the access allowed
cannot disagree. An auditor keeps the console; a person with neither role
gets `Account`. **Write the choice once**, for example as a constructor
`Chrome::for_person(username, role)`, and have every `/me` page use it.
`MeShellData.is_admin` (`pages/me_security.rs`) is the wrong input if it is
not exactly that predicate: check what it holds, and replace it if it
differs.

**The account menu is unchanged** in `Account`: *My account*, *Sign out*.
**Check that sign-out works for a person outside the console**: it posts to
`/admin/logout`. Measure it, and say so in the return.

## §2 — tests

- `layout/tests.rs`: `Account` renders the account menu with the name and
  **no** console link (none of the seven `/admin…` links in `Nav`'s list).
- **The chooser, not only the choices**: `Chrome::for_person` gives `Console`
  for admin and auditor, and `Account` for a user. **Mutation:** make it
  return `Console` always; red.
- **e2e**: a person with neither role, signed in, on each `/me` route that
  renders a page (`/me/security/overview`, `…/password`, `…/mfa`,
  `…/passkeys`, `…/sessions`, `…/language`, `/me/apps`; build the list from
  the router and state its length). Each response has the account menu, and
  **no `href="/admin`** except the sign-out form's `action`. Then the same
  routes as an admin: the console navigation is there. A non-admin session
  can be made the way the review did: the dev client's authorization flow,
  or the e2e fixtures' equivalent.
- **Sign-out**, as that person: it ends the session (§1).
