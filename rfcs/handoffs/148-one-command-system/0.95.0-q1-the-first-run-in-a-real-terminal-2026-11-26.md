## §1 — what the binary does today (`crates/sui-id/src/cli/first_run.rs`)

- **Bare `sui-id` or `sui-id serve`, with no `--config` and no configuration file**, decides on
  `stdin().is_terminal() && stderr().is_terminal()`.
- **In a terminal**, it prints *"sui-id needs a configuration file to start. Create one now?"*, then three choices, then
  `choice [l/p/n]: `, all on stderr. It reads one line:
  - `l` writes the local-trial configuration through `run_init` and **does not serve**;
  - `p` writes the production template, the same way;
  - anything else (`n`, empty, an unexpected `x`, end of input) prints the guidance and exits 1. Nothing is written.

## §2 — the test: through the binary, in a real terminal, with no new dependency

**Use util-linux's `script`**: `script -q -e -c "<binary>" /dev/null`, with the test piping the answer into `script`'s stdin.
`script` gives the child a real pseudo-terminal for stdin, stdout and stderr. The `-e` option returns the child's exit code.
No Rust crate is added. O2b's review rejected a pty crate for one test, and that reasoning still holds.

Add the tests to `crates/sui-id/tests/e2e/o2b_init_and_first_run.rs`, beside the no-terminal ones. Each runs in a fresh
temporary directory, with the same kind of wall-clock hang guard `run_bounded` has.

| Test | Answer | Asserts |
|---|---|---|
| the offer appears, and `n` writes nothing | `n` | the output contains *"Create one now?"* and `choice [l/p/n]`; exit 1; no `sui-id.toml` |
| `l` writes the local trial, and does not serve | `l` | exit 0; `sui-id.toml` exists and is **byte-identical** to what `sui-id init` writes in an empty directory; the process exited rather than serving |
| `p` writes the production template | `p` | exit 0; byte-identical to what `sui-id init --production` writes |
| an unexpected answer is "not now" | `x` | exit 1; nothing written |
| end of input is "not now" | stdin closed after the prompt | exit 1; nothing written. **Measure how `script` passes end of input on this util-linux version.** If it cannot be passed reliably, say so, and drop this row rather than make it flaky |

**Mutations**, each run and reverted:
1. `stdin_and_stderr_are_terminals()` returns `false`: the offer is never shown, and the `n` and `l` rows fail;
2. `l` mapped to the production template: the byte comparison fails.

**If `script` is not on the machine, the test fails, naming it. It never skips.** A skipped test is how the terminal case
went untested for a release. Say in the return which util-linux version you ran under, and **expect CI's `ubuntu-24.04`
runner to be the confirmation**: it is not confirmable locally.
