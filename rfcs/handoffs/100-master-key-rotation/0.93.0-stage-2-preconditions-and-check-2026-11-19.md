## §1 — the preconditions, gathered in one place

One function, `rotation_preconditions(...)`, run **before anything is
created**, returns **every** failing precondition, not only the first. The
list is `implementation.md`'s:

| # | Precondition | How |
|---|---|---|
| P1 | the key came from the file, not the environment | stage 1's `KeyOrigin`; keep today's refusal text |
| P2 | the active key opens the sentinel | `keyring::resolve_checked` (stage 1), read-only |
| P3 | no leftover `<key>.new`, and no leftover workspace `<key>.rotation-work` | through the adapter's metadata, never `std::fs` (stage 0's rule) |
| P4 | **one filesystem** for the active, next, temporary, workspace and backup paths | they are all siblings, so this is **the key file is a regular file, not a symlink**, and its directory is the one the renames happen in. A symlinked key file would have `rename` replace the link and leave the target, which is the opposite of activation. Refuse it (RFC 100 M6), naming the link and its target |
| P5 | the adapter's primitives work there | §2: probed in a real rotation only |

Each refusal names its path and what to do. **No key bytes, ever**;
fingerprints only.

## §2 — `--check`: read-only, and honest about what it cannot check

`sui-id admin master-key rotate --check` (and the old `admin rotate-key
--check`, the same arguments) runs **P1 to P4 and creates nothing**. No
prompt, no database opened for writing, and no file created, removed or
renamed. **In Simulated, it records no operation.** It prints each
precondition with its result, then exits 0 if all pass and 1 if any fails.

**P5 cannot be checked without writing**: proving that the filesystem
honours `create_new`, `fsync`, `hard_link`, `rename` and a directory sync
needs a file to try them on. So:
- **`--check` does not probe**, and says so in its output, one line: *"not
  checked here: whether this filesystem supports the operations rotation
  needs; a rotation probes that first, with a temporary file it removes."*
- **A real rotation probes first**, after P1 to P4 pass and before anything
  else: a probe file, `<key>.rotation-probe`, taken through every primitive
  and removed. A primitive that fails refuses the rotation, and the probe
  file is removed or named.

This keeps `implementation.md`'s rule, *"`--check` records no operation"*,
true, rather than calling a probe "read-only".

**The real rotation runs the same function**, then P5, then today's sequence.
The two hand checks at `:443-452` and `:457-470` move into it; their texts
are kept.

## §3 — tests

- **Each of P1 to P4 refuses before any file exists**: in Simulated, no
  operation recorded, for each, on both `--check` and a real rotation.
- **`--check` records no operation, on success and on refusal**, in Simulated
  (`implementation.md`'s own test).
- **`--check` reports every failing precondition at once**: set up P3 and P4
  failing together, and both are named.
- **P5's probe**: under Failpoint, make each primitive fail in turn. The
  rotation refuses, no `.new` or backup exists afterwards, and the probe
  file does not remain.
- **Through the binary**: `admin master-key rotate --check` on a healthy
  instance exits 0 and leaves the directory byte-identical (hash every
  file before and after). With a symlinked key file it exits 1, naming it.
- **Mutation:** move P3's check after the staged key is written; the "before
  any file exists" test fails.
